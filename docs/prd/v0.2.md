# 面习 PRD v0.2

当前要做出来的产品。本地运行，数据在自己的机器上。它是通用的面试练习，不是只给一个人写死的本子。

## 定位

用户粘贴岗位描述或自己的方向，创建一个项目，然后为这个方向收集知识点。可以同时开着「AI 产品经理」和「AI Native 前端」。练习是一场完整的模拟面试：有面试官、会根据回答追问。先做文字，并留好语音入口。一场结束之后给出分数、指出错漏和思路缺口，并更新掌握度。

## 项目

一个项目有名称、方向和可选的 JD。项目之间互不覆盖。删除项目只去掉这条准备线，不删除别人还在用的知识点，也不清掉已经形成的全局掌握度。

## 知识模型

一个知识点是 Obsidian 仓库里的一篇 Markdown，frontmatter 至少有 `id`、`title`、`aliases`、`projects`、`sources`、`created`。

关系同时用两种方式表达，并且要能查询：

- 正文里的 wiki 链接
- frontmatter 或关系表里的 `prerequisite`、`related`、`part_of`

SQLite 保存项目、场次、回答、分数、掌握度、复习日程，以及知识点与边的投影。筛选和排序读数据库，不在每次请求时扫完整仓库。

知识点可以挂到多个项目。掌握度的主键是知识点 id。在一个项目里掌握之后，另一个项目的模拟面试不再出这道题，也不再记一份新分数。

## 采集

新项目不能是空的。

- 上传 txt、md；有文字层的 pdf 也收。抽成知识点，写入仓库和数据库。
- 按 JD 在本地笔记里匹配。匹配不足三篇时，用通用种子补上，并写一篇「岗位理解」。
- 如果配置了 `TAVILY_API_KEY`，补齐时可以再检索几条。没有密钥就明确告诉用户走的是本地库，而不是假装搜过网。

## 模拟面试

开一场时选择严格或宽松。面试官按人设提问，并根据回答追问一层：缺了关键点就追那个点，已经覆盖了就往下挖一个情景。

没有 `OPENAI_API_KEY`（或 `INTERVIEW_LLM_API_KEY`）时，用内置脚本完成整场，包括追问和评分。有密钥时走兼容 OpenAI 的接口；调用失败则退回脚本。

本轮优先考还没掌握、以及到期且尚未掌握的点。已经掌握或熟练的点不进入模拟面试。复习模式可以指定这些点，到期再练。

语音先留钩子：同一条提交接口接受 `modality: "text" | "voice"`。界面可以把一段转写标成语音回答。这一版不接麦克风。

## 评分与掌握度

每条回答有相关性、正确性、完整度、推理，以及这四项的均分。反馈包含讲错的地方、没覆盖的要点、更好的讲法。

一个知识点在本场的分数是它各条回答的均分。若已有掌握度，新分数按 55% 本场、45% 原来的分数混合，所以一次复习可以升也可以降。

下次复习：

| 等级 | 分数 | 间隔 |
| --- | --- | --- |
| 薄弱 | 小于 55 | 低于 45 为 1 天，否则 2 天 |
| 熟悉中 | 55–74 | 低于 65 为 3 天，否则 5 天 |
| 已掌握 | 75–89 | 低于 82 为 7 天，否则 14 天 |
| 熟练 | ≥ 90 | 低于 95 为 21 天，否则 30 天 |

「今天」按 Asia/Shanghai。

## 总览

总览要能看到：

- 今天练过的知识点，其当前掌握度均值
- 今天的场次、回答数、涉及的知识点
- 优势和薄弱，能按分数、标题、下次复习排序
- 今天的缺口：低分或没覆盖的要点
- 作答历史，带相关知识点，能按时间和四项分数排序
- 到点的聊天式提醒。提醒是数据，不是只在表里的一行日期

## 每日复习

复习表列出到期、逾期、即将到来和尚未排期的知识点。每行有等级、分数、关联项目、上次和下次时间。可以从一行直接开始复习，即使这个点已经掌握。

薄弱点会生成一条当天就能看见的缺口提醒；到了复习日再有一条复习提醒。

## 验收

克隆仓库后按 README 启动 API 和网页，能打开演示项目，做一场短面试，并在总览上看到今天的练习量和掌握度变化。没有模型密钥时这条路径也要通。

## 不做

- 飞书
- 严格 / 宽松以外的面试官人设
- 按公司做的微调
- 依赖某台机器上的绝对路径
